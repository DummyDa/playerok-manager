# Подарки MRKT с блокировкой передачи

Проверено 29 октября 2026 года по сохранённым ответам `/api/v1/gifts/saling` и опубликованному JavaScript интерфейса MRKT. Покупки в ходе исследования не выполнялись.

- `nextTransferDate` — момент доступности передачи/вывода в Telegram. Карточка показывает `transfer-timer` с этой датой; будущая дата запрещает вывод в интерфейсе.
- `isTransferable: true` — фильтр запроса поиска. Бот также передаёт `isPremarket: false` и `giftType: "Upgraded"`.
- `isLocked: true` — дополнительный запрет вывода на стороне MRKT.
- `returnLockedUntil` — дополнительный срок ограничения возврата, используемый для игровых подарков.
- `exportDate` — отдельный срок экспорта в блокчейн; будущая дата сама по себе не запрещает передачу в Telegram.
- `unlockDate` и `nextGiveAvailableAt` используются для розыгрышей, поэтому не служат самостоятельным запретом обычной передачи.

В опубликованном коде `fv(date)` сравнивает дату с текущим временем. Таймер карточки использует `fv(gift.nextTransferDate)`, запрет вывода — `fv(gift.nextTransferDate) || gift.isLocked || gift.giftType !== Upgraded`.

Первичные источники:

- [Код карточек и вывода MRKT](https://cdn.tgmrkt.io/js/app-shared-ApPazGe8.js).
- [Схема фильтров MRKT](https://cdn.tgmrkt.io/js/filters.schema-91X6aVWk.js).

Бот проверяет доступность при поиске и непосредственно перед запросом покупки. Пропущенное поле `nextTransferDate` или нераспознаваемая дата не считаются доказательством доступности. Устаревшая котировка с заблокированным подарком загружается заново. Если предложений нет, закупка не выполняется, объявление остаётся активным. При необходимости поиск переходит на следующую страницу; он ограничен десятью страницами.

Эти поля относятся к текущей версии API MRKT. Дополнительные ограничения Telegram после фактического вывода по-прежнему проверяются отдельно через `can_transfer_at`.
