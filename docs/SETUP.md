# Установка и подключение аккаунтов

## 1. Установка на Windows

Нужны **Python 3.12 или новее**, **Node.js 22 LTS или новее** и **Git**. При установке Python включите Add Python to PATH. Git используется pip для установки зафиксированной зависимости PlayerokAPI.

1. Скачайте репозиторий ZIP-архивом и распакуйте его либо клонируйте через Git.
2. Откройте папку проекта и запустите `setup.bat`.
3. Дождитесь сообщения «Готово». Установка создаёт `.venv`, устанавливает зависимости, применяет миграции и собирает интерфейс.
4. Запустите `run.bat`. Откроется <http://localhost:3100>.
5. Создайте пароль администратора — минимум 10 символов.

Редактировать `.env` и копировать чужие базы или сессии не нужно. Первое открытие создаёт чистую локальную базу, без примеров магазина и подключённых аккаунтов. Внешние подключения настраиваются в **Настройки**. Покупки, передача, изменение цен и платные поднятия изначально выключены.

`status.bat` показывает процессы. `stop.bat` останавливает API, интерфейс и воркер. Закрытие вкладки браузера работу не останавливает. Компьютер должен оставаться включённым.

## 2. Playerok

1. Войдите в свой аккаунт на `playerok.com` в обычном браузере.
2. Нажмите F12 → Network / «Сеть» и обновите страницу Playerok.
3. Выберите запрос к `playerok.com`, например `graphql`.
4. В Headers → Request Headers найдите **Cookie**.
5. Скопируйте полное **значение** заголовка; слово `Cookie:` добавлять не нужно.
6. В панели: **Настройки → Playerok → Cookies Playerok → Сохранить cookies**.
7. Нажмите **Проверить**, затем **Лоты → Синхронизация**.

Cookies дают доступ к аккаунту. Не отправляйте их в issues, переписку или репозиторий. Они сохраняются в зашифрованной локальной базе, не возвращаются в ответы API. После выхода из аккаунта в браузере или истечения сессии cookies может потребоваться заменить.

Проверка показывает отдельные признаки: сохранены ли реквизиты, прошёл ли запрос, время последнего успеха и последнюю ошибку. Наличие cookies само по себе не означает рабочее подключение.

## 3. Telegram-бот для уведомлений

Этот бот отвечает за уведомления и команды. Он **не заменяет личный Telegram-аккаунт**, через который работает MRKT и выдача NFT.

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, задайте название и username бота.
3. Вставьте выданный токен в **Настройки → Telegram-бот**.
4. Укажите свой username без `@` либо числовой Telegram ID. Числовой ID не зависит от смены username.
5. Нажмите **Сохранить бота**, затем **Проверить бота**.
6. Убедитесь, что тот же токен не используется другим запущенным экземпляром программы.
7. Ниже в **Режим работы** включите **Telegram-уведомления и команды** и сохраните торговые настройки.
8. Со своего аккаунта откройте созданного бота и отправьте `/start`.

Если указан только username, первый разрешённый `/start` привязывает числовой ID владельца. Чужие команды не принимаются. Доступные команды: `/start`, `/status`, `/stop`. `/stop` включает аварийную остановку новых торговых действий.

Замена токена или username отключает polling и сбрасывает старую привязку владельца. После замены повторите включение уведомлений и `/start`. Для удаления токена есть отдельная кнопка.

## 4. Личный Telegram

1. Откройте [my.telegram.org/apps](https://my.telegram.org/apps) и войдите со своим номером.
2. В **API development tools** создайте приложение, если оно ещё не создано.
3. Скопируйте **API ID** и **API Hash** в одноимённые поля панели. Это не токен BotFather.
4. Укажите телефон в международном формате: `+код_страныномер`, без пробелов.
5. Нажмите **Получить код**. Ключи сохранятся автоматически.
6. Код обычно приходит в приложение Telegram. Введите его только в поле **Код из Telegram** в своей локальной панели.
7. Если Telegram запросит двухэтапную проверку, появится отдельное поле пароля 2FA.
8. Дождитесь сообщения о сохранённой сессии.

Код и пароль не записываются в очередь задач или журнал. Временное состояние авторизации хранится зашифрованным и истекает через 10 минут. После проверки одноразовые данные удаляются. При неверном коде или пароле можно повторить соответствующий шаг; при истёкшем коде начните заново. При прерывании сетевого шага перезапуском новый код автоматически не запрашивается.

Кнопка **Отключить Telegram** отключает сессию в этой панели и разрешения закупки/выдачи. Для отзыва серверной авторизации используйте **Telegram → Настройки → Устройства**. Старые импортированные файлы сессий остаются локальными резервными данными и не публикуются.

Перед сменой подключений при включённых торговых функциях нажмите «Стоп». Вход сам по себе не разрешает торговые действия и сбрасывает подтверждение отдельного тестирования выдачи.

## 5. MRKT

MRKT использует личный Telegram из предыдущего шага. Отдельный пароль MRKT вводить не нужно.

1. Сначала откройте MRKT в Telegram со своего аккаунта и завершите начальную регистрацию/согласия сервиса, если они запрошены.
2. В панели нажмите **Подключить / проверить MRKT**.
3. При успехе появятся статус подключения и доступный баланс.
4. Перейдите в **NFT Gifts**, обновите каталог коллекций и загрузите модели выбранной коллекции.

Проверка MRKT выполняет авторизацию и чтение баланса, а не покупку NFT. При HTTP 401 повторите проверку. При 429 дождитесь окончания ограничения запросов. Если сервис изменил API, обновите приложение; неизвестный формат ответа не считается успешным подключением.

## 6. Прокси и публичный доступ

По умолчанию соединения прямые. В **Дополнительные параметры подключений** можно задать:

- HTTP/SOCKS-прокси Playerok;
- HTTP/SOCKS-прокси Telegram Bot API;
- MTProxy личного Telegram, например `tg://proxy?server=HOST&port=PORT&secret=SECRET`;
- User-Agent и таймаут Playerok;
- адрес MRKT API;
- точный публичный HTTPS-адрес панели, если вы самостоятельно настроили HTTPS-прокси или туннель.

Пустое поле существующего токена, API Hash или прокси **не заменяет** сохранённый секрет. Для удаления прокси нажмите отдельную кнопку отключения. Секретные значения обратно в браузер не загружаются.

Панель слушает только loopback: интерфейс `127.0.0.1:3100`, API `127.0.0.1:8101`. Указание публичного адреса само по себе не создаёт хостинг или туннель. Не открывайте API напрямую в интернет. Для удалённого доступа нужны HTTPS и существующий пароль администратора; разрешён только указанный источник. Публичный адрес меняйте из локальной вкладки.

## 7. Первые лоты и обычные товары

После синхронизации все объявления видны в порядке Playerok. Обычные товары можно редактировать и поднимать. **Закупка MRKT и автовыдача к ним не применяются**, даже при включённой общей автоматизации.

Для Telegram NFT откройте **Лоты → Тип товара / модель**, выберите **Telegram NFT** и точную пару **коллекция — модель**. Новую пару можно создать прямо в окне привязки или создания объявления. Само создание пары не покупает NFT и не меняет объявление.

Затем настройте комиссии, себестоимость Star, желаемую прибыль, округление, ограничения цены и при необходимости конкурентов. Сохраните и подтвердите профиль комиссий. Кнопка **Расчёт** показывает закупку, передачу, комиссии, прибыль и рекомендуемую цену; применение цены требует отдельного действия.

### Премиум в расчёте прибыли

В **Автоцены → Целевая прибыль** настройте **Премиум в себестоимости**. По умолчанию тариф учитывается у лотов с премиум-статусом и с включённым расписанием поднятий. Можно выбрать «Всегда учитывать» или «Не резервировать» для общей стратегии либо конкретного NFT-лота.

**Поднятий на одну продажу** — плановое количество оплат премиума, по умолчанию одна. Если одно объявление до продажи поднимается несколько раз, укажите нужное число. Это расчётный резерв, он сам по себе не запускает оплату.

Стоимость запрашивается у Playerok для конкретного лота и предполагаемой цены продажи. Если цена меняется, пересчитывается и тариф. Устаревший или недоступный тариф блокирует расчёт; произвольный процент вместо него не подставляется.

В предварительном расчёте и таблице автоцен премиум показан отдельной строкой. Прибыль считается после закупки, передачи, премиума и комиссий. Рядом доступна прибыль при текущей цене объявления. Если вручную добавляли резерв премиума в комиссии, уберите ту строку, чтобы не посчитать расход дважды.

В финансовом отчёте учитываются подтверждённые расходы на поднятия, а не расчётный резерв. Все оплаченные через приложение поднятия вычитаются один раз, включая повторные. Для платежей вне приложения историческая стоимость не выдумывается. Обычные товары сохраняют ручную выдачу; запросы MRKT для них не запускаются.

## 8. Расписания поднятий

В **Поднятиях** отметьте нужные лоты либо нажмите **Выбрать все**. Задайте общий интервал, лимит одной покупки и включение расписания, затем **Сохранить для выбранных**. В общих настройках отдельно задаются дневной бюджет и разрешение платных поднятий.

Тариф запрашивается для конкретного объявления и его текущей цены. Для просмотра стоимости выберите один лот. Удаление расписания — корзина справа, затем подтверждение. История расходов сохраняется. Уже отправленный платёж удаление расписания не отменяет.

## 9. Включение реальных действий

Проверьте предварительные расчёты, балансы, комиссии и лимиты. Нулевые лимиты запрещают расходы. Общие разрешения на переоценку, премиум, закупку и передачу включаются отдельно.

Закупка и MTProto-передача реализованы, но успешный реальный сквозной тест NFT не входит в автоматические проверки этого репозитория. Переключатель **«Выдача отдельно протестирована мной»** предназначен для владельца после своего теста на конкретном аккаунте. Он не заменяет проверку ограничений Telegram, точного NFT, получателя и платной передачи.

Недоступная модель не отключает объявление. Неопределённый результат денежного запроса требует сверки; автоматический повтор не выполняется. Первая синхронизация старых заказов не запускает их выдачу. Импортированные ручные заказы повторно не исполняются.

## 10. Резервные копии и обновление

### Обновления из панели

Приложение проверяет ветку `main` репозитория `DummyDa/playerok-manager` при каждом запуске сервера, затем каждые 15 минут. Проверка выполняется в фоне и не задерживает открытие панели. Проверить сразу можно в **Настройки → Обновления приложения**. При новом коммите появляется плашка с описанием изменений.

- **Посмотреть обновление** открывает описание и ссылку на коммит. Само открытие ничего не устанавливает.
- **Позже** скрывает этот коммит. Следующий новый коммит снова покажет плашку. Скрытое предложение можно вернуть из настроек.
- **Установить обновление** — отдельное подтверждение. Автоматизация приостанавливается, службы завершают работу, сохраняются база, ключ, настройки и сессии. Затем устанавливаются зависимости, собирается интерфейс и приложение перезапускается.

Установка может занимать несколько минут. Приложение перезапускается само, браузер восстанавливает связь и автоматически открывает готовую новую версию. Вручную перезапускать приложение не нужно. Даже если вкладка была в фоне, проверка продолжится при возвращении. Кнопка **Открыть новую версию** остаётся запасным способом обновить страницу. Автоматизация остаётся на паузе: проверьте работу и при необходимости нажмите **Возобновить**.

Установка кнопкой работает для отдельного чистого Git-репозитория. Для новой установки с поддержкой обновлений:

```powershell
git clone https://github.com/DummyDa/playerok-manager.git
cd playerok-manager
setup.bat
run.bat
```

Локальные правки исходников блокируют автоустановку: установщик их не перезаписывает. Файлы в `data` и `.env` не мешают обновлению и не отправляются на GitHub. Если ветка сервера изменилась после подтверждения или обновление не продолжает установленную историю Git, установка остановится до замены исходников.

Для ZIP-копии доступна проверка новых коммитов после первого наблюдения, но установка выполняется вручную: остановите старую программу, скачайте новую версию в отдельную папку, перенесите свою папку `data`, выполните `setup.bat`, затем `run.bat`. Старую папку сохраните до проверки.

### Если обновление не установилось

Копия перед установкой находится в `data/updates/backup-…`, журнал — `data/updates/install.log`. Эти файлы приватные. При ошибке после замены исходников установщик пытается восстановить старый код, данные и зависимости, затем запустить прежнюю версию с приостановленной автоматизацией. Недоступность сети или несовместимые зависимости могут потребовать ручного восстановления.

Если автоматическое восстановление не завершилось, не включайте торговые функции. Остановите приложение, подготовьте прежнюю версию в отдельной папке, скопируйте в неё содержимое `backup-…/data` как папку `data`, выполните `setup.bat` и `run.bat`. Нужный коммит прежней версии указан в `backup-…/version.json`. Восстанавливайте базу вместе с ключом и сессиями. Базы и ключи никогда не прикладывайте к issues.

Ежедневные копии SQLite находятся в `data/backups`, хранятся последние семь. Создать копию вручную можно в настройках. Для полного переноса остановите программу и сохраните **всю папку `data`**, особенно `manager.sqlite3`, `secrets.key` и импортированные `.session`.

Без ключа `secrets.key` зашифрованные реквизиты не восстановить. Копии содержат приватные данные и не должны попадать в GitHub. Для обновления остановите службы, сделайте резервную копию, обновите исходники, выполните `setup.bat`, затем `run.bat`.

Пароль администратора меняется в **Настройки → Пароль панели**. Остальные сеансы панели после смены пароля завершаются.

## 11. Ошибки

| Симптом | Что проверить |
| --- | --- |
| Playerok не подключён | Cookies сохранены полностью и ещё действуют; нажмите Проверить |
| Бот не отвечает | Верный токен и владелец, уведомления включены, нет второго polling-процесса |
| Telegram не прислал код | Код мог прийти в Telegram; API ID/Hash и номер верны; при ограничении подождите |
| Требуется 2FA | Введите облачный пароль Telegram в появившееся поле, не код из SMS |
| MRKT не подключён | Сначала войдите в личный Telegram; завершите регистрацию в MRKT; проверьте соединение |
| Цена не рассчитывается | NFT-пара, свежие котировка и курс, себестоимость Star, подтверждённые комиссии |
| Сервер временно недоступен | Дождитесь запуска служб, проверьте status.bat и data/logs; перед повторным сохранением проверьте его результат |
| Порт занят | Остановите другой экземпляр; текущие порты 3100 и 8101 |

Если создаёте issue, прикладывайте описание, версию Python/Node и обезличенный текст ошибки. Никогда не прикладывайте `.env`, папку `data`, HAR, cookies, токены, пароли или Telegram-сессию.
