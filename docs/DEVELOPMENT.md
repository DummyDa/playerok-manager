# Разработка

## Структура

- `backend/app` — FastAPI, SQLite, расчёты, очередь, интеграции и Telegram-авторизация.
- `backend/migrations` — миграции Alembic.
- `frontend` — Next.js, React, TypeScript, Tailwind, локальные шрифты.
- `scripts` — установка, запуск, экспорт OpenAPI, импорт прототипа, проверка публикации.
- `tests` — тесты backend без внешней сети.
- `data` — **только локальные** база, ключ, сессии, логи и резервные копии; не публикуется.

## Команды

Из корня после `setup.bat`:

```powershell
.venv\Scripts\python.exe -m pytest tests -q
.venv\Scripts\python.exe scripts\export_openapi.py
npm.cmd run generate:api --prefix frontend
npm.cmd run typecheck --prefix frontend
npm.cmd run build --prefix frontend
```

Для браузерных тестов:

```powershell
cd frontend
npx playwright install chromium
npm test
```

Браузерные тесты подменяют ответы API и не покупают NFT, не оплачивают поднятия и не передают подарки. Backend-тесты запрещают внешний HTTP. Для ручного чтения своих реальных данных используйте тестовую локальную сессию `scripts/qa_session.py`, а после проверки — `scripts/qa_session.py cleanup`. Её токен хранится только внутри игнорируемой `data/qa`, действует 10 минут и не меняет пароль администратора.

В режиме разработки API и воркер запускаются отдельными процессами, интерфейс — `npm run dev --prefix frontend`. Не запускайте второй воркер или второй polling-процесс того же бота.

## Подключения

Настройки подключений хранятся в таблице `secrets` под ключами `config:*`, зашифрованы Fernet локальным `data/secrets.key`. `Config.get` читает их динамически; пустое сохранённое значение перекрывает старое значение `.env`. Воркер сбрасывает клиент MRKT при изменении ревизии конфигурации.

`GET /api/v1/connections/config` возвращает только публичные поля и флаги наличия секретов. Токены, API Hash, прокси с паролем, cookies, телефон, коды и строки сессии не возвращаются. Ошибки валидации не содержат исходных секретных значений.

Авторизация Telegram проходит по `/connections/telegram-user/start`, `/code`, `/password`, `/cancel`. В очереди хранятся только ID входа и название шага. Временная StringSession, phone-code hash и одноразовый ввод шифруются. Воркер выполняет один сетевой шаг за раз, удаляет код/пароль перед запросом и не повторяет прерванный шаг автоматически. Успешная StringSession остаётся зашифрованной. Импортированные SQLite-сессии поддерживаются для совместимости, но не требуются новым пользователям.

## Импорт старого проекта

Импорт запускается только явно и не изменяет исходный проект:

```powershell
.venv\Scripts\python.exe scripts\import_legacy.py --source C:\path\to\prototype
.venv\Scripts\python.exe scripts\import_legacy.py --source C:\path\to\prototype --apply
```

Первая команда — предварительный отчёт. Перед применением выполните миграции новой базы. Импорт идемпотентен, копирует реквизиты в шифрованное хранилище, cookies, Telegram-сессию через SQLite backup, историю и ручные задания. Личные примеры лотов и конкурентов не добавляются. Торговые разрешения старого проекта не наследуются.

## Публикация

Проверка обновлений выполняется воркером каждые 15 минут через публичный GitHub API. `GET /api/v1/updates` читает только кеш и локальную Git-версию. `POST /check` ставит задачу; `/dismiss` скрывает один коммит; `/install` принимает ровно подтверждённый SHA и требует административную сессию и CSRF. Сетевой сбой не мешает открытию панели.

Установщик копируется в `data/updates/runner.py` и запускается независимо от API и воркера. Он принимает только чистый checkout и точное продолжение истории `main` фиксированного репозитория. После остановки служб создаётся согласованная копия SQLite и приватных файлов. После установки или восстановления остаётся аварийная остановка. Сценарии успеха/отката тестируются с заменой сетевых клиентов и процессов; реальная установка в рабочем магазине автоматически в тестах не выполняется.

```powershell
.venv\Scripts\python.exe scripts\check_release.py --archive data\release\playerok-manager.zip
```

Команда использует явный список допустимых исходников. Она отвергает файлы `.env`, базы, ключи, сессии, HAR и логи, проверяет исходники и сборку на совпадения с реальными локальными секретами, затем создаёт архив и манифест SHA-256. При отсутствии локальной базы проверяется только допустимый состав файлов. Архив не включает `data`, `.venv`, зависимости и результаты сборки.

Публиковать исходники можно без локальных подключений. Никогда не используйте `git add -f` для `data` или `.env`. Для воспроизводимого первоначального набора зависимостей сохранены `requirements.lock.txt` и `frontend/package-lock.json`; PlayerokAPI зафиксирован на конкретном commit.
