# Docker на VPS (Linux)

`compose.yaml` запускает API, воркер, каталог и панель. Используется host networking Linux, но HTTP-процессы слушают **только 127.0.0.1**: 8101, 3180 и 3100. Наружу публикуется nginx, направляющий домен каталога на 3180. Панель открывается через SSH-туннель.

## Файлы и запуск

В корне проекта нужны приватный `.env`, `data/manager.sqlite3`, `data/secrets.key` и используемая Telegram-сессия. На сервер переносите данные только после остановки старого воркера и каталога. Папки `.venv`, `node_modules`, `.next` с Windows не переносятся. Не запускайте два воркера магазина на разных машинах.

Каталог хранит отдельный кэш в `catalog/data`. Его можно перенести или собрать заново. Каталоги данных и `.env` должны быть доступны контейнерному UID 10001. Пароль панели и коды хранятся в общей базе; ключ шифрования обязателен. Данные и секреты исключены из контекста сборки через `.dockerignore`.

```sh
docker compose build api
docker compose build dashboard
docker compose up -d --no-build
docker compose ps
docker compose logs --tail 50 worker
```

API применяет миграции до запуска, затем healthcheck разрешает запуск остальных служб. Контейнеры автоматически запускаются при перезагрузке VPS. Обновление кода выполняется пересборкой образов; встроенный установщик Git для Docker не используется.

## HTTPS и доступ владельца

Шаблон nginx: `deploy/nginx/catalog.conf.template`. Замените `__DOMAIN__` на домен, выпустите сертификат Certbot через webroot `/var/www/playerok-acme`, проверьте `nginx -t` и перезагрузите nginx. В настройках каталога сохраните публичный HTTPS-адрес.

nginx должен **перезаписывать** `X-Real-IP` значением `$remote_addr`. `CATALOG_TRUSTED_PROXY` в Compose разрешает этот заголовок только для loopback-соединения с настроенным публичным Host. Не направляйте домен каталога на порт панели или API.

```powershell
ssh -N -L 127.0.0.1:3100:127.0.0.1:3100 root@SERVER_IP
```

Открывайте панель по `http://127.0.0.1:3100`. Для остановки: `docker compose stop`. Перед резервным копированием остановите контейнеры либо используйте SQLite backup API; обычное копирование активного SQLite-файла без WAL не гарантирует целостность.
